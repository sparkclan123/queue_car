# คิวรถ · QueueCar

ระบบจัดการคิวรถและงานวิ่งภาษาไทย เน้นมือถือ ใช้ React + TypeScript + Firebase Spark

- เว็บใช้งาน: https://queue-car-sparkclan.web.app
- ตัวอย่างที่แยกจากข้อมูลจริง: https://queue-car-sparkclan.web.app/?demo=1
- Firebase: https://console.firebase.google.com/project/queue-car-sparkclan/overview

## การใช้งาน

**Guest** เปิดเว็บได้ทันที ไม่ต้องสมัครหรือล็อกอิน ดูข้อมูลคนรถและเบอร์โทร คิว งานวิ่ง การเงิน หลักฐาน ประวัติยกเลิก และกิจกรรมได้ครบ รวมรายงานช่วงวันที่และ CSV แต่เพิ่ม แก้ไข เปลี่ยนสถานะ หรือยกเลิกรายการไม่ได้

**ผู้ดูแล** กดเข้าสู่ระบบด้วย Google บัญชีที่มีสิทธิ์ เริ่มจาก “คนรถ → เพิ่มคนรถ → ลงคิว → จ่ายงาน → จบงาน” โดยลงคิวใหม่หลังจบงานได้ ผู้ดูแลยกเลิกคิวพร้อมเหตุผล หรือกด “ย้ายไปท้ายคิว” จากเมนู `…` การย้ายเปลี่ยนเวลาลงคิวและบันทึกกิจกรรม

งานหนึ่งเที่ยวเลือกจุดส่ง/จังหวัดพ่วงตามลำดับได้ 1–8 จุด งานวันอนาคตเริ่มสถานะรอออกงาน เมื่อจ่ายงานจะนำรถออกจากคิวและล็อกคนรถไว้กับงานนั้นจนกว่าจะจบหรือยกเลิก

การเงินแยกเป็นเบิกเงิน ค่าใช้จ่าย ค่าซ่อมรถ และหักเงิน ระบุคนรถ ผู้รับเงิน วันที่ เหตุผล และแนบรูปได้สูงสุด 10 รูปต่อรายการ เลือกหลายรูปพร้อมกันหรือทยอยเพิ่มได้ เริ่มเป็นรอดำเนินการ เมื่อจ่าย/หักจริงแล้วให้ยืนยันสถานะ **ระบบบันทึกข้อมูลเท่านั้น ไม่มีบริการโอนเงินจริง** รายการผิดสามารถยกเลิกแล้วเพิ่มรายการที่ถูกต้อง ยอดสรุปนับเฉพาะรายการที่ดำเนินการแล้วตามเดือน สามารถกรองคนรถ/ประเภท/สถานะและส่งออก CSV ได้

เมนู **เซลล์** เก็บชื่อ เบอร์โทรไทย และรายละเอียดลูกค้า/พื้นที่/งานที่ดูแล ผู้ดูแลเพิ่มและแก้ไขได้พร้อมบันทึกประวัติกิจกรรม Guest ค้นหา ดูรายละเอียดเต็ม และกดโทรได้ รองรับเบอร์มือถือ เบอร์สำนักงาน เลขไทย และรูปแบบ `+66` โดยเก็บเป็นเบอร์ขึ้นต้น `0` รายชื่อโหลดแบบเรียลไทม์เฉพาะเมื่อเปิดหน้าเซลล์ในคอลเลกชัน `salesContacts` และข้อมูลตัวอย่างแยกจากฐานข้อมูลจริง

## บอร์ดคิวและรายงานช่วงวันที่

หน้าภาพรวมแสดงจำนวนรถรอคิวปัจจุบันก่อนเสมอ พร้อม 4 คิวแรกและปุ่มดูทั้งหมด คิวไม่เปลี่ยนตามตัวกรองรายงาน แตะชื่อคนรถจากคิว ทะเบียนคนรถ รายงานงานวิ่ง หรือรายการการเงิน เพื่อดูรายงานรวมของคนนั้นได้

ถัดจากคิวคือ **ความเคลื่อนไหววันนี้** แสดงชื่อคนรถ ทะเบียน จังหวัดพ่วงตามลำดับ และสถานะของเที่ยววิ่งที่ลงวันที่วันนี้ (เวลาไทย) แบบเรียลไทม์ ไม่รวมงานยกเลิก แสดง 4 เที่ยวล่าสุดก่อนและกดดูงานวันนี้ทั้งหมดได้ การเลือกวันอื่นในหน้างานวิ่งหรือช่วงรายงานไม่เปลี่ยนส่วนนี้ หากไม่มีงานแสดง **ยังไม่มีข้อมูล รถดำเนินการวันนี้** ผู้เข้าชมที่ไม่ได้ล็อกอินก็ดูและเปิดรายละเอียดได้

รายงานเริ่มจาก **ต้นเดือนถึงวันนี้ (เวลาไทย)** วันที่สิ้นสุดเริ่มต้นใหม่เป็นวันนี้ทุกครั้งที่เปิดเว็บ และขยับตามวันใหม่ถ้ายังไม่ได้เลือกวันอื่นเอง ระบุวันที่เริ่มต้น–สิ้นสุดแล้วกดดูรายงาน หรือใช้ปุ่มวันนี้ / 7 วันล่าสุด / เดือนนี้ วันที่ทั้งสองขอบเขตนับรวมด้วย

- แสดงเที่ยววิ่ง จังหวัดและจังหวัดพ่วง แยกรอออกงาน / กำลังวิ่ง / จบงาน รายการยกเลิกงานยังเปิดดูได้แต่ไม่นับเป็นเที่ยว
- ผู้ดูแลเห็นเบิกเงิน ค่าใช้จ่าย ค่าซ่อม ค่าขึ้นงานแทน และยอดหัก แยกรายการรอดำเนินการจากดำเนินการแล้ว
- ยอดเบิกและค่าใช้จ่ายรวมทั้งรายการรอจ่ายและจ่ายแล้ว แต่ไม่นับรายการยกเลิก ยอดหักใช้หลักเดียวกัน
- **จ่ายสุทธิแล้ว = ยอดจ่ายที่ดำเนินการแล้ว − ยอดหักที่ดำเนินการแล้ว** ไม่ใช่เงินเดือนคงเหลือ และอาจติดลบเมื่อยอดหักมากกว่ายอดจ่ายในช่วงนั้น
- รายงานรายคนรถมีรายละเอียดเที่ยววิ่ง เส้นทาง รายการเงิน ผู้รับเงิน หลักฐานที่แนบ และเหตุการณ์ยกเลิกหรือขึ้นงานแทน พร้อม CSV
- Guest เห็นรายงานทุกหมวด รวมเงิน เหตุผลยกเลิกและหลักฐานได้เหมือนผู้ดูแล โดยไม่มีสิทธิ์เขียนข้อมูล

รายงานโหลดจากเซิร์ฟเวอร์ตามช่วงวันที่และแบ่งอ่านครั้งละ 500 เอกสาร จึงไม่ใช้ยอดที่ถูกตัดจากหน้ารายวัน/รายเดือนเดิม รายงานอัปเดตเมื่อเปิด เปลี่ยนช่วง กดรีเฟรช หรือบันทึกรายการในหน้าเว็บนี้ ส่วนคิวปัจจุบันติดตามแบบเรียลไทม์ หากคอลเลกชันใดเกิน 20,000 รายการในช่วงเดียว ระบบแจ้งให้ลดช่วงวันที่และไม่แสดงยอดบางส่วนเป็นยอดทั้งหมด

## โทรหาคนรถและการใช้งานมือถือ

แตะแถวคิวส่วนชื่อ/ทะเบียนเพื่อเปิดรายละเอียดคนรถ ปุ่ม **โทร** อยู่เหนือรายงาน และมีปุ่มโทรลัดข้างคิวกับหน้าทะเบียนคนรถ เมื่อมีเบอร์ที่ใช้งานได้จะใช้ลิงก์ `tel:` เปิดแอปโทรศัพท์ของอุปกรณ์ ไม่โทรอัตโนมัติเมื่อเปิดรายละเอียด ถ้าไม่มีเบอร์ไม่แสดงปุ่มโทร ผู้ดูแลเพิ่มเบอร์ได้จาก “คนรถ → แก้ไข”

เบอร์รองรับเลขไทย เลขสากล ช่องว่าง ขีด วงเล็บ และรหัสประเทศ + ปฏิเสธข้อความ/URL หรือรหัสพิเศษที่ไม่ใช่เบอร์โทร ปุ่มโทรและเมนูจัดการมีพื้นที่แตะอย่างน้อย 44px เมนูมือถือแสดงครบ 6 หน้าเหมือนกันทั้ง Guest และผู้ดูแล

## สถานะก่อนจ่ายงาน

ลงคิวแล้วเริ่มเป็น **รอคิว** ผู้ดูแลกด `…` ของรถในหน้าภาพรวมหรือหน้าคิว → **กำลังไปขึ้นงาน** → ยืนยันสถานะได้ รถยังอยู่ในลำดับเดิมและนับรวมในคิวปัจจุบัน ยังไม่สร้างเที่ยววิ่งหรือรายการเงิน Guest เห็นสถานะใหม่แบบเรียลไทม์ ผู้ดูแลเปลี่ยนกลับเป็นรอคิวได้จากเมนูเดียวกัน จากนั้นจ่ายงานตามขั้นตอนเดิม เมื่อจ่ายงานแล้วรถจึงออกจากคิว

คิวเก่าที่ไม่มีฟิลด์ `status` แสดงเป็นรอคิวโดยไม่ต้องแก้ข้อมูลย้อนหลัง การย้ายท้ายคิวหรือแก้ชื่อคนรถคงสถานะไว้ ส่วนการลงคิวรอบใหม่เริ่มรอคิวเสมอ การเปลี่ยนสถานะบันทึกประวัติกิจกรรม และป้องกันการแก้คิวเก่าที่ถูกจ่ายงาน ยกเลิก ลงใหม่ หรือเปลี่ยนสถานะจากอีกเครื่องแล้ว

## ยกเลิกคิวและขึ้นงานแทน

ผู้ดูแลกดเมนู `…` ของคิว → ยกเลิกคิว ระบุเหตุผล และเลือกผู้ขึ้นแทนจากรถที่อยู่ในคิวและพร้อมรับงาน **ถ้ามี** หากเลือกคนแทนต้องระบุวันออกงานและจังหวัด 1–8 จุด ระบบสร้างงานให้คนแทน นำคนเดิมและคนแทนออกจากคิว และล็อกคนแทนกับงานนั้น

ระบุยอดหักคนยกเลิก ผู้รับยอดหัก และยอดให้คนแทนแยกกันได้ ยอดไม่จำเป็นต้องเท่ากัน ไม่คิดเงินให้ใส่ 0 ระบบสร้างรายการหัก / ค่าขึ้นงานแทนอัตโนมัติในสถานะ **รอดำเนินการ** เมื่อจ่ายหรือหักจริงแล้วจึงยืนยันในหน้าการเงิน ไม่ต้องบันทึกเงินซ้ำ

การลบคิว สร้างงานแทน บันทึกประวัติ และสร้างรายการเงินอยู่ใน Firestore transaction เดียวกัน หากคิวเปลี่ยนไปหรือคนแทนไม่พร้อมจะไม่บันทึกบางส่วน การกดซ้ำหรือสองเครื่องทำพร้อมกันจะไม่สร้างยอดซ้ำ ประวัติยกเลิกและยอดตกลงแก้ย้อนหลังไม่ได้ ส่วนรายการเงินใช้สถานะยกเลิกได้ และรายงานตัดยอดนั้นออก การยกเลิกก่อนมีฟีเจอร์นี้ยังอยู่ในประวัติกิจกรรมเดิม ไม่มีการเดายอดหรือคนแทนย้อนหลัง

## ข้อมูลและสิทธิ์

- `queue`, `jobs`: สาธารณะ อ่านได้โดยไม่ต้องล็อกอิน มีเฉพาะชื่อที่ใช้แสดง ทะเบียน ประเภทรถ ลำดับคิว/งาน จังหวัด และหมายเหตุสาธารณะ
- `drivers`, `entries`, `entries/{id}/evidence`, `cancellations`, `audits`: ทุกคนอ่านได้ตามสิทธิ์ Guest ของระบบ รวมเบอร์โทร รายการเงิน รูปหลักฐาน เหตุผลยกเลิกและประวัติ ผู้ดูแลเท่านั้นที่เขียนตามกฎของแต่ละรายการ
- `settings`: จำกัดเฉพาะผู้ดูแล ส่วนรายชื่อสิทธิ์ `admins` ทั้งหมดอ่านได้เฉพาะผู้ดูแลหลัก
- `cancellations` เชื่อมรายการเงินด้วย `entries.cancellationId` และงานแทนด้วย `replacementJobId` เหตุผลและยอดเงินไม่ถูกใส่ในเอกสารงานสาธารณะ
- ผู้ดูแลหลักคือ `porthachapong@gmail.com` ต้องเข้าสู่ระบบ Google และยืนยันอีเมล บัญชีนี้แต่งตั้ง/ถอดสิทธิ์ผู้ดูแลได้ผ่านเมนู **สมาชิก** และเปลี่ยนสิทธิ์ของตัวเองจากเว็บไม่ได้ (กำหนดตรงกันใน `firestore.rules` และ `src/lib/members.ts`)
- `admins/{lowercaseEmail}`: สมาชิกอ่านสิทธิ์ตัวเองได้ ผู้ดูแลหลักเท่านั้นที่สร้างหรือเปลี่ยน `active` ได้ ผู้ดูแลทั่วไปจัดการคิว/งาน/เงินได้ แต่จัดการสิทธิ์สมาชิกไม่ได้
- `members/{uid}`: บันทึกชื่อ อีเมลที่ยืนยันแล้ว และเวลาเข้าใช้ล่าสุดเมื่อเข้าสู่ระบบ Google สมาชิกเขียนได้เฉพาะโปรไฟล์ตัวเองและเพิ่มฟิลด์สิทธิ์ไม่ได้ ผู้ดูแลหลักอ่านรายชื่อทั้งหมดได้ Guest และผู้ดูแลทั่วไปอ่านรายชื่อสมาชิกไม่ได้
- เมนูสมาชิกเพิ่มสิทธิ์ด้วยอีเมลล่วงหน้าได้ ไม่ส่งอีเมลเชิญ ผู้ใช้ต้องล็อกอิน Google ด้วยอีเมลที่ระบุ รายชื่อผู้ใช้ที่เคยใช้แอปรุ่นเก่าจะแสดงหลังเข้าแอปอีกครั้ง
- `memberAudits` เก็บประวัติเปลี่ยนสิทธิ์พร้อมเวลาเซิร์ฟเวอร์ใน batch เดียวกับการเปลี่ยนสิทธิ์ อ่านได้เฉพาะผู้ดูแลหลัก และแก้หรือลบจากเว็บไม่ได้
- กฎตรวจ Google provider, email_verified และสถานะ `active` ทุกครั้งที่เขียนข้อมูล แอปฟังสิทธิ์ของบัญชีปัจจุบันแบบ realtime จึงเปลี่ยนจากผู้ดูแลเป็นผู้ชมได้โดยไม่ต้องออกแล้วเข้าใหม่
- รายการเงินและประวัติกิจกรรมไม่ถูกลบ/แก้ยอดย้อนหลังในเว็บ ใช้การยกเลิกและสร้างรายการใหม่
- Google Login ใช้ redirect ผ่าน `queue-car-sparkclan.firebaseapp.com` ซึ่งเป็นโดเมนเดียวกับ Firebase Auth เพื่อรองรับเบราว์เซอร์มือถือที่บล็อกคุกกี้ข้ามโดเมน ปุ่มล็อกอินบน `web.app` จะพาไปโดเมนนี้โดยอัตโนมัติ
- Firebase config ของเว็บเป็นข้อมูลสาธารณะตามปกติ แอปโหลด `/__/firebase/init.json` จาก Firebase Hosting ไม่มี service-account key หรือ token ฝังในเว็บ
- สิทธิ์ Google Login เก็บผ่าน Firebase Auth ส่วนข้อมูล Firestore ใช้แคชในหน่วยความจำ ไม่เปิด persistent offline cache สำหรับข้อมูลการเงิน

### กราฟและวันที่บนมือถือ

ภาพรวมและรายงานคนรถมีปุ่ม **รายการ / กราฟ** ใช้วันที่เริ่มต้น–สิ้นสุดชุดเดียวกัน เลือกดูยอดเบิกเงิน จำนวนครั้งที่เบิก เที่ยววิ่ง หรือเบิกและค่าใช้จ่ายรวมได้ กราฟภาพรวมแตะชื่อคนรถเพื่อดูรายละเอียดได้ ส่วนรายคนแสดงกราฟตามวันที่มีรายการ

ยอดและจำนวนครั้งที่เบิกนับเฉพาะรายการประเภท `advance` ที่ไม่ถูกยกเลิก รวมทั้งรอจ่ายและจ่ายแล้ว ส่วนค่าใช้จ่ายรวมรวมค่าซ่อมและค่าขึ้นงานแทนแต่ไม่รวมยอดหัก เที่ยววิ่งนับงานที่ไม่ถูกยกเลิก รวมรอออกงาน และงานพ่วงหลายจังหวัดยังนับเป็นหนึ่งเที่ยว

ช่องวันที่และเดือนใช้หน้าตาร่วมกัน มีปฏิทิน native ของอุปกรณ์อยู่ด้านใน คงชื่อฟิลด์ การตรวจวันที่และการใช้คีย์บอร์ด โดยกรอบไม่ขยายตามขนาดช่องวันที่ของเบราว์เซอร์ ข้อความวันที่ในช่องใช้วัน/เดือน/ปี ค.ศ.

คิวใช้ Firestore transaction พร้อมตัวนับเวลา `settings/queue` ทำให้การลงคิว/ย้ายท้ายคิวเรียงลำดับได้เมื่อมีผู้ดูแลหลายเครื่อง การจ่ายงานสร้างงาน ลบคิว และล็อกคนรถในธุรกรรมเดียวกัน

## แผนฟรีและรูปหลักฐาน

ใช้ **Spark**, Firebase Hosting, Firestore Standard ที่ `asia-southeast1`, Google Authentication ไม่มี Cloud Functions และไม่ใช้ Cloud Storage ไม่ผูก billing account

[Cloud Storage ต้องใช้ Blaze](https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024) จึงเก็บภาพ JPEG ที่ย่อแล้วในเอกสาร Firestore ที่เปิดอ่านได้ตามสิทธิ์ Guest รูปต้นฉบับรับ JPG/PNG/WebP ไม่เกิน 15 MB ย่อด้านยาวเริ่มที่ 1,600 px บีบอัดเป็น JPEG โดยลดคุณภาพก่อนลดความละเอียดเพิ่มเติม จำกัด data URL 270,000 ตัวอักษรต่อรูป (ไฟล์ JPEG ไม่เกินประมาณ 200 KB) ฟอร์มแสดงจำนวนรูป ความคืบหน้า และขนาดไฟล์รวมก่อน–หลังย่อ เตรียมทีละรูปเพื่อไม่ใช้หน่วยความจำพร้อมกันมากเกินไป รูปที่อ่านไม่ได้จะแจ้งแยกและเก็บรูปที่ผ่านไว้ รูปเดิมที่บันทึกแล้วเปิดดูได้ตามปกติ ปิด index ของข้อมูลรูป โหลดรูปเฉพาะเมื่อเปิดดู และเก็บต้นฉบับไว้นอกระบบหากต้องใช้รายละเอียดเต็ม

ฟรีภายใน [โควตา Firebase](https://firebase.google.com/pricing): Firestore เก็บ 1 GiB, อ่าน 50,000 เอกสาร/วัน, เขียน 20,000/วัน; Hosting พื้นที่ 10 GB และ transfer 360 MB/วันตามตาราง Spark ควรดู Usage ใน Console เป็นระยะ **ฟรีไม่ใช่ไม่จำกัด** เมื่อโควตาเต็มอาจใช้งานไม่ได้จนรีเซ็ต แผน Spark ไม่คิดค่าเกินโควตาอัตโนมัติ

หน้าคิวอ่านรถที่รอทั้งหมดเพื่อให้จำนวนปัจจุบันถูกต้อง งานวิ่งติดตามงานทั้งหมดของวันนี้และวันที่กำลังเลือกใน listener เดียว (ถ้าเป็นวันเดียวกันอ่านเพียงวันเดียว) เพื่อให้ภาพรวมวันนี้ไม่หายเมื่อดูย้อนหลัง ทะเบียนคนรถแสดงสูงสุด 500 และหน้าเมนูการเงินเดิม 1,000 รายการต่อเดือน ประวัติกิจกรรมล่าสุด 30 รายการ **ใช้รายงานช่วงวันที่บนหน้าภาพรวมสำหรับยอดรวมครบช่วง** ซึ่งมี pagination แยกต่างหาก ช่วงวันที่ยาวขึ้นใช้โควตาอ่านมากขึ้น

โหมดตัวอย่างใช้ข้อมูลสมมติใน localStorage ของอุปกรณ์เท่านั้น รูปทดลองอยู่ในหน่วยความจำและหายเมื่อรีเฟรช ไม่ส่งข้อมูลตัวอย่างเข้า Firestore

## พัฒนาและตรวจสอบ

ต้องมี Node.js 22 ขึ้นไป

```sh
npm ci
npm run dev
# เปิด http://localhost:5173/?demo=1
npm test
npm run build
```

ทดสอบสิทธิ์ด้วย Firebase Emulator ต้องมี Java 21 ขึ้นไปใน PATH:

```sh
npm run test:rules
```

การทดสอบครอบคลุม Guest/บัญชีที่ไม่ได้สิทธิ์/อีเมลไม่ยืนยัน การห้ามเพิ่มสิทธิ์เอง สิทธิ์ Guest อ่านข้อมูลและหลักฐานได้แต่เขียนไม่ได้ ลิงก์โทรที่ปลอดภัย การย้ายคิว การจ่ายงานพร้อมกัน รูปหลักฐาน จำนวนเงินและการเปลี่ยนสถานะ รวมถึงหน่วยสตางค์ วันที่ไทย และ CSV formula injection

## Deploy

```sh
firebase login
npm run deploy
```

`.firebaserc` ชี้ `queue-car-sparkclan` แล้ว Deploy ทั้งกฎ Firestore/indexes และ Hosting ไม่เปิด billing ใช้ `firebase projects:list` เพื่อตรวจบัญชีก่อน deploy

สคริปต์ `scripts/firebase-admin.mjs` ใช้บัญชี Firebase CLI ปัจจุบันเท่านั้น ไม่บันทึก token ลงไฟล์ คำสั่ง `inspect` ตรวจโปรเจกต์/Google provider และ `seed-admin` ตั้งค่าผู้ดูแลหลักเดิม ต้องมี IAM ของโปรเจกต์ ไม่ต้องใช้สคริปต์นี้ในการใช้งานเว็บปกติ
