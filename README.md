# คิวรถ · QueueCar

ระบบจัดการคิวรถและงานวิ่งภาษาไทย เน้นมือถือ ใช้ React + TypeScript + Firebase Spark

- เว็บใช้งาน: https://queue-car-sparkclan.web.app
- ตัวอย่างที่แยกจากข้อมูลจริง: https://queue-car-sparkclan.web.app/?demo=1
- Firebase: https://console.firebase.google.com/project/queue-car-sparkclan/overview

## การใช้งาน

**Guest** เปิดเว็บได้ทันที ไม่ต้องสมัครหรือล็อกอิน ดูคิวปัจจุบัน งานตามวันที่ เส้นทางหลายจังหวัด และดาวน์โหลด CSV งานวิ่งได้

**ผู้ดูแล** กดเข้าสู่ระบบด้วย Google บัญชีที่มีสิทธิ์ เริ่มจาก “คนรถ → เพิ่มคนรถ → ลงคิว → จ่ายงาน → จบงาน” โดยลงคิวใหม่หลังจบงานได้ ผู้ดูแลยกเลิกคิวพร้อมเหตุผล หรือกดไอคอน “ย้ายไปท้ายคิว” ได้โดยตรง การย้ายเปลี่ยนเวลาลงคิวและบันทึกกิจกรรม

งานหนึ่งเที่ยวเลือกจุดส่ง/จังหวัดพ่วงตามลำดับได้ 1–8 จุด งานวันอนาคตเริ่มสถานะรอออกงาน เมื่อจ่ายงานจะนำรถออกจากคิวและล็อกคนรถไว้กับงานนั้นจนกว่าจะจบหรือยกเลิก

การเงินแยกเป็นเบิกเงิน ค่าใช้จ่าย ค่าซ่อมรถ และหักเงิน ระบุคนรถ ผู้รับเงิน วันที่ เหตุผล และแนบรูปได้ 3 รูปต่อรายการ เริ่มเป็นรอดำเนินการ เมื่อจ่าย/หักจริงแล้วให้ยืนยันสถานะ **ระบบบันทึกข้อมูลเท่านั้น ไม่มีบริการโอนเงินจริง** รายการผิดสามารถยกเลิกแล้วเพิ่มรายการที่ถูกต้อง ยอดสรุปนับเฉพาะรายการที่ดำเนินการแล้วตามเดือน สามารถกรองคนรถ/ประเภท/สถานะและส่งออก CSV ได้

## ข้อมูลและสิทธิ์

- `queue`, `jobs`: สาธารณะ อ่านได้โดยไม่ต้องล็อกอิน มีเฉพาะชื่อที่ใช้แสดง ทะเบียน ประเภทรถ ลำดับคิว/งาน จังหวัด และหมายเหตุสาธารณะ
- `drivers`: เฉพาะผู้ดูแล รวมเบอร์โทรและสถานะล็อกงาน
- `entries`, `entries/{id}/evidence`, `audits`, `settings`: เฉพาะผู้ดูแล
- `admins/{lowercaseEmail}`: ผู้ใช้ Google ที่ยืนยันอีเมลแล้วอ่านสิทธิ์ตัวเองได้ แก้สิทธิ์จากเว็บไม่ได้ ต้องใช้ Firebase Console หรือเครื่องมือผู้ดูแลที่มี IAM
- กฎตรวจทั้ง Google provider, email_verified และ `active: true` ในเอกสารสิทธิ์ ไม่ใช่อนุญาตให้ทุกบัญชี Google แก้ข้อมูล
- บัญชีผู้ดูแลตั้งต้นได้ provision ใน Firestore แล้ว ใช้เอกสาร `admins` เป็นแหล่งสิทธิ์จริง
- รายการเงินและประวัติกิจกรรมไม่ถูกลบ/แก้ยอดย้อนหลังในเว็บ ใช้การยกเลิกและสร้างรายการใหม่
- Google Login ใช้ redirect ผ่าน `queue-car-sparkclan.firebaseapp.com` ซึ่งเป็นโดเมนเดียวกับ Firebase Auth เพื่อรองรับเบราว์เซอร์มือถือที่บล็อกคุกกี้ข้ามโดเมน ปุ่มล็อกอินบน `web.app` จะพาไปโดเมนนี้โดยอัตโนมัติ
- Firebase config ของเว็บเป็นข้อมูลสาธารณะตามปกติ แอปโหลด `/__/firebase/init.json` จาก Firebase Hosting ไม่มี service-account key หรือ token ฝังในเว็บ
- สิทธิ์ Google Login เก็บผ่าน Firebase Auth ส่วนข้อมูล Firestore ใช้แคชในหน่วยความจำ ไม่เปิด persistent offline cache สำหรับข้อมูลการเงิน

คิวใช้ Firestore transaction พร้อมตัวนับเวลา `settings/queue` ทำให้การลงคิว/ย้ายท้ายคิวเรียงลำดับได้เมื่อมีผู้ดูแลหลายเครื่อง การจ่ายงานสร้างงาน ลบคิว และล็อกคนรถในธุรกรรมเดียวกัน

## แผนฟรีและรูปหลักฐาน

ใช้ **Spark**, Firebase Hosting, Firestore Standard ที่ `asia-southeast1`, Google Authentication ไม่มี Cloud Functions และไม่ใช้ Cloud Storage ไม่ผูก billing account

[Cloud Storage ต้องใช้ Blaze](https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024) จึงเก็บภาพ JPEG ที่ย่อแล้วในเอกสาร Firestore ส่วนตัว รูปต้นฉบับรับ JPG/PNG/WebP ไม่เกิน 15 MB ย่อด้านยาวเริ่มที่ 1,600 px และปรับลดตามขนาด จำกัด data URL 600,000 ตัวอักษรต่อรูป (ประมาณ 450 KB ของไฟล์ JPEG) ปิด index ของข้อมูลรูป โหลดรูปเฉพาะเมื่อเปิดดู และเก็บต้นฉบับไว้นอกระบบหากต้องใช้รายละเอียดเต็ม

ฟรีภายใน [โควตา Firebase](https://firebase.google.com/pricing): Firestore เก็บ 1 GiB, อ่าน 50,000 เอกสาร/วัน, เขียน 20,000/วัน; Hosting พื้นที่ 10 GB และ transfer 360 MB/วันตามตาราง Spark ควรดู Usage ใน Console เป็นระยะ **ฟรีไม่ใช่ไม่จำกัด** เมื่อโควตาเต็มอาจใช้งานไม่ได้จนรีเซ็ต แผน Spark ไม่คิดค่าเกินโควตาอัตโนมัติ

เพื่อควบคุมจำนวนอ่าน แอปอ่านคิวสูงสุด 200, งานสูงสุด 200 ต่อวันที่เลือก, คนรถ 500 และการเงิน 1,000 ต่อเดือน ประวัติกิจกรรมล่าสุด 30 รายการ หากข้อมูลเกินจำนวนดังกล่าวต้องเพิ่ม pagination ก่อนใช้งานในขนาดนั้น อย่าใช้ยอดรวมเป็นรายงานครบถ้วนเมื่อเกินขอบเขตนี้

โหมดตัวอย่างใช้ข้อมูลสมมติใน localStorage ของอุปกรณ์เท่านั้น รูปทดลองอยู่ในหน่วยความจำและหายเมื่อรีเฟรช ไม่ส่งข้อมูลตัวอย่างเข้า Firestore

## พัฒนาและตรวจสอบ

ต้องมี Node.js 22 ขึ้นไป

```sh
npm ci
npm run dev
# เปิด http://localhost:5173/?demo=1
npm test
npm run build
```

ทดสอบสิทธิ์ด้วย Firebase Emulator ต้องมี Java 21 ขึ้นไปใน PATH:

```sh
npm run test:rules
```

การทดสอบครอบคลุม Guest/บัญชีที่ไม่ได้สิทธิ์/อีเมลไม่ยืนยัน การห้ามเพิ่มสิทธิ์เอง การป้องกันเผยเบอร์โทรในข้อมูลสาธารณะ การย้ายคิว การจ่ายงานพร้อมกัน รูปหลักฐาน จำนวนเงินและการเปลี่ยนสถานะ รวมถึงหน่วยสตางค์ วันที่ไทย และ CSV formula injection

## Deploy

```sh
firebase login
npm run deploy
```

`.firebaserc` ชี้ `queue-car-sparkclan` แล้ว Deploy ทั้งกฎ Firestore/indexes และ Hosting ไม่เปิด billing ใช้ `firebase projects:list` เพื่อตรวจบัญชีก่อน deploy

สคริปต์ `scripts/firebase-admin.mjs` ใช้บัญชี Firebase CLI ปัจจุบันเท่านั้น ไม่บันทึก token ลงไฟล์ คำสั่ง `inspect` ตรวจโปรเจกต์/Google provider และ `seed-admin` ตั้งค่าผู้ดูแลหลักเดิม ต้องมี IAM ของโปรเจกต์ ไม่ต้องใช้สคริปต์นี้ในการใช้งานเว็บปกติ
